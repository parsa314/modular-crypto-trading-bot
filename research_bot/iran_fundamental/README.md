# موتور پژوهش بنیادی ایران — برش نخست 0.1.0

`evidence_state: ENGINEERING`؛ این تغییر یک مسیر مهندسی برای دریافت بستهٔ مدرک،
کنترل عددی، تهیهٔ پروندهٔ فارسی و ایمیل درخواستی است. نسخهٔ فعلی برای ادعاهای
بارگذاری‌شده، اصالت منبع را تأیید نمی‌کند و همیشه تصمیم
`INSUFFICIENT_INFORMATION` می‌دهد. داشتن نشانی کدال، شاهد تأیید شدن داده نیست.

## قرارداد بستهٔ مدرک

نمونهٔ ساختگی قابل اجرا در `tests/fixtures/iran_equity_engineering.json` است؛
این فایل صورت مالی واقعی نیست و ارسال ایمیل آن ممنوع است.

`schema_version=1.0.0`، `issuer` شامل `issuer_id, symbol, name, industry,
share_class=ORDINARY`، `documents` شامل `document_id, source_url,
publication_at, period_start, period_end, scope, report_type, raw_text` و
`facts` شامل `variable, value, unit, document_id, source_quote` الزامی است.

- تاریخ انتشار، ISO با منطقه زمانی است؛ تاریخ‌های دوره مالی، میلادی ISO هستند.
  درخواست بدون تاریخ مبنا، زمان درخواست را ثبت می‌کند؛ retry همان کلید، همان
  تصویر اولیه را برمی‌گرداند. استخراج هرگز به تاریخ مبنا عقب برده نمی‌شود.
- واحدها: `IRR`، `TOMAN` با ضریب آشکار ۱۰، `MILLION_IRR`، `BILLION_IRR` و
  `SHARES`. پول در خروجی ریال است. ارقام متنی یا عدد صحیح پذیرفته می‌شوند؛
  float، NaN، infinity و ابهام واحد رد می‌شوند.
- صورت‌های مالی `ANNUAL` یا `INTERIM_YTD` پذیرفته می‌شوند. انتخاب فقط از اسناد
  منتشرشده تا تاریخ مبنا و یک scope صورت می‌گیرد؛ جدیدترین پایان دوره و سپس
  انتشار انتخاب می‌شود. اسناد متعارض هم‌تاریخ ترکیب نمی‌شوند.
- شاهد هر رقم باید در متن مدرک باشد و همان مقدار را داشته باشد؛ این بررسی
  جایگزین احراز اصالت، انطباق برچسب حساب یا بررسی اصلاحیهٔ رسمی نیست.
- برای EPS از سود قابل انتساب و میانگین موزون سهام استفاده می‌شود. برای نسبت
  CFO در صورت تلفیقی، `net_income` کل لازم است؛ سود پس از کسر اقلیت مخرج آن نیست.
- حد ورودی: ۴ مگابایت، ۲۰ سند، ۱۰۰۰ رقم؛ متن هر سند حداکثر ۱ مگابایت.

ستون‌های هر رقم: `Variable | Value | Unit | Period | Report_Type | Source_URL |
Publication_Date | Extraction_Date | Status`، به‌علاوهٔ مقدار/واحد اصلی و شاهد.
وضعیت ارقام این نسخه `ESTIMATED` با برچسب صریح «فرض موقت بارگذاری‌شده» است؛
کاربر نمی‌تواند با ارسال `VERIFIED` داده را تأیید کند. نتیجهٔ محاسبه نیز
`ESTIMATED_FROM_UNVERIFIED_INPUTS` است. دادهٔ مفقود، ارزش‌گذاری و سود نرمال‌شده
به‌صورت تهی و همراه دلیل گزارش می‌شوند.

## اجرای محلی بدون ایمیل

از ریشهٔ مخزن:

```bash
python -m research_bot.iran_fundamental \
  --symbol آزمون \
  --bundle tests/fixtures/iran_equity_engineering.json \
  --database /tmp/iran-research.sqlite \
  --output /tmp/iran-reports \
  --idempotency-key engineering-demo
```

خروجی شامل `report.json`، `report.html` و `facts.csv` در پوشهٔ شناسهٔ کار است.
SQLite متن مدرک، گزارش، هش‌ها و وضعیت تحویل را پایدار نگه می‌دارد. کلید یکسان
با محتوای یکسان همان گزارش را برمی‌گرداند؛ تغییر محتوا با همان کلید خطاست.
کلید تازه یک درخواست مستقل است. متن HTML escape می‌شود و CSV متن اجرایی
صفحه‌گسترده را خنثی می‌کند؛ JSON مرجع دقیق مقادیر عددی باقی می‌ماند.

## API و ایمیل فقط با درخواست

سرویس به‌صورت پیش‌فرض این مسیریاب را فعال نمی‌کند. تنظیمات محیط اجرا:

| متغیر | کاربرد |
|---|---|
| `IRAN_FUNDAMENTAL_ENABLED=true` | فعال‌سازی مسیریاب پژوهش |
| `IRAN_RESEARCH_DB` | مسیر SQLite روی حجم پایدار؛ نه `:memory:` |
| `IRAN_RESEARCH_API_TOKEN` | توکن خصوصی حداقل ۳۲ کاراکتر |
| `IRAN_RESEARCH_RECIPIENT` | گیرندهٔ ثابت مالک، خارج از مخزن |
| `IRAN_GMAIL_ACCESS_TOKEN` | OAuth کوتاه‌عمر Gmail با مجوز send، اختیاری |

هیچ کلید یا نشانی شخصی در نمونهٔ عمومی ثبت نمی‌شود. اتصال Gmail در جلسهٔ
ChatGPT به معنی وجود OAuth موتور مستقر نیست. مدیریت تمدید توکن در این نسخه
پیاده نشده است؛ توکن منقضی‌شده تحویل موفق محسوب نمی‌شود. فعال‌سازی ناقص
مسیر پژوهش، خطای شروع سرویس می‌دهد.

تمام مسیرها به `Authorization: Bearer <runtime-token>` نیاز دارند:

| روش/مسیر، با پیشوند `/research/iran-equities` | رفتار |
|---|---|
| `POST /analyses` | symbol، idempotency_key، evidence_bundle؛ as_of و scope اختیاری |
| `GET /analyses/{job_id}` | گزارش ثابت و وضعیت جاری تحویل |
| `GET /analyses/{job_id}/html` | گزارش فارسی RTL |
| `GET /analyses/{job_id}/delivery` | وضعیت و رسید ارائه‌دهنده |
| `POST /analyses/{job_id}/deliver` | ارسال صریح یک درخواست ایمیلِ ثبت‌شده |

`send_email=false` پیش‌نمایش بدون ایمیل است. مقدار پیش‌فرض true فقط هنگام
همین درخواست تحلیل به گیرندهٔ تنظیم‌شده ارسال را ثبت می‌کند. نبود گیرنده
خطای 409 می‌دهد؛ نبود transport گزارش را با `QUEUED` برمی‌گرداند. درخواست
نمی‌تواند گیرنده را تغییر دهد و مسیر deliver برای پیش‌نمایش، outbox نمی‌سازد.
هیچ برنامهٔ دوره‌ای اجرا نمی‌شود.

ثبت گزارش و outbox تراکنشی است. تحویل تنها با claim اتمیک از `QUEUED` به
`SENDING` می‌رود. `SENT` به رسید Gmail نیاز دارد؛ رد قطعی `FAILED` و خطای
مبهم `DELIVERY_UNCERTAIN` است. crash در حین ارسال، `SENDING` باقی می‌گذارد.
هر دو وضعیت مبهم نیاز به تطبیق دستی دارند؛ retry خودکار وجود ندارد. این
سیاست از ارسال کور تکراری جلوگیری می‌کند و ادعای exactly-once شبکه ندارد.
`report.delivery_state` تصویر زمان ساخت است؛ پاسخ API در `delivery` وضعیت
فعلی را می‌دهد. خطای ایمیل، شکست فرضیهٔ مالی محسوب نمی‌شود.

## اعتبارسنجی و مرحلهٔ بعد

```bash
python -m unittest discover -s tests -p test_iran_fundamental.py -v
python -m compileall -q research_bot/iran_fundamental research_bot/service.py
```

آزمون‌ها دارای oracle عددی مستقل، دیسک واقعی، درخواست هم‌زمان، تاریخ انتشار
آینده، انطباق scope، عدم جعل تأیید منبع، HTML/CSV، API احرازشده، گیرندهٔ ثابت،
فرستندهٔ شبیه‌سازی‌شده و حفظ وضعیت سرویس رمزارزی هستند. ایمیل واقعی یا دادهٔ
مالی واقعی در آزمون‌ها استفاده نمی‌شود. CI فعلی مخزن همین آزمون‌ها را در
مجموعهٔ pytest اجرا می‌کند؛ نیازی به workflow جدید نیست.

| گیت | برچسب این برش |
|---|---|
| کنترل علّی تاریخ/واحد/تکرار و سازگاری مسیر سرویس | PASS پس از آزمون مهندسی |
| اصالت داده رسمی، گزارش حسابرس و پوشش اصلاحیه‌ها | INCONCLUSIVE |
| اقتصاد معامله، هزینه معامله، PBO/DSR، n معاملات و mean_net | N/A؛ پژوهش معاملاتی اجرا نشده |
| ادعای سود یا نتیجه prospective v0.51 | N/A؛ هیچ ادعایی ثبت نمی‌شود |

گام بعدی واحد: افزودن adapter کدال/TSETMC با نمونهٔ واقعی قابل بازیابی، احراز
هویت ناشر، نسخه‌های اصلاحیه، هش مدرک و کنترل تاریخ انتشار؛ سپس عبور ارقام از
ورودی تأییدنشده به شواهد تأییدشده، قبل از توسعهٔ ارزش‌گذاری خودکار.
