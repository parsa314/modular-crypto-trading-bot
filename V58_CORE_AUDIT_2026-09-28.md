# V58 Core Implementation Audit — 2026-09-28

## Verdict

The repository contains substantive V58 code, but the earlier description of a complete autonomous AI trading bot was unsupported. Before this repair, the V58 modules were not connected by an executable end-to-end runner, several tests could pass without emitting the claimed event type, and important isolation classes accepted invalid access patterns.

Current status: **research software path implemented and reproducibly executed; scientific trading system remains NO_GO**.

## Defects reproduced and repaired

| Area | Reproduced defect | Repair and fresh evidence |
|---|---|---|
| Execution time | Entry semantics allowed the signal/next-open boundary to be represented inconsistently | Decision timestamp is the closed signal bar end and exact next-bar open; a missing immediate open fails closed |
| Barrier labels | Intrabar outcomes were timestamped at bar open and paths could omit bars | Intrabar/timeout labels become available at close; paths must start at entry and remain contiguous; STOP_FIRST is enforced |
| Strategy arms | ARM_C did not enforce a strict multi-bar causal chain; ARM_E tests could pass without a generated event | Sweep, displacement and MSS require ordered distinct bars and frozen references; a nonempty synthetic test generates all five Arms |
| Feature causality | Input was silently sorted; nonfinite OHLCV and gaps were not rejected | Ordered UTC, finite values, nonnegative volume and contiguous timeframe are mandatory; future-mutation tests are nonempty |
| Holdout | String/purpose combinations could bypass intended isolation | Explicit purpose-to-partition allow-list; final evaluation needs a separate authorization flag |
| Preprocessing | Scaler could fit validation rows | Scaler fits DEVELOPMENT only; row identities are unique and audited |
| Calibration | Stub returned success without fitting a calibrator | It validates VALIDATION inputs and raises `NotImplementedError`; no fake fitted state is exposed |
| Risk admission | Cost, drawdown, duplicate intent and cash checks existed only as isolated fragments | Atomic, in-memory research admission connects these gates; it creates no paper/live order |
| Runtime | No V58 end-to-end command existed | `python -m research_bot.v58 synthetic-demo --output <dir>` executes generator → regime → next-open → barrier → cost → ledger |
| Data evidence | Existing real archives were not frozen by the V58 intake | 10 datasets / 51,100 H4 rows were byte-audited twice with identical manifest hash |

## Implemented software boundary

`OHLCV → causal features → causal regime → ARM_A–E candidates → exact next-open entry → frozen ATR barrier → TP/SL/TIMEOUT → cost accounting → evidence ledger`

The risk admission path covers cost gate, abstention, drawdown veto, duplicate-intent rejection and cash reservation. A complete multi-asset portfolio allocator, exchange adapter, trained meta-model and implemented calibrator are not present.

4. Calibration algorithms, uncertainty estimation and expected-utility model selection remain unimplemented.
5. Portfolio correlation/cluster exposure and realistic partial-fill/latency/market-impact simulation remain incomplete.
6. PostgreSQL integration was skipped locally because no test database was available.
