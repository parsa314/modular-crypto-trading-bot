## Objective

Build the comparison machinery before adding larger neural networks or reinforcement learning.

Stage 6 compares strategy-conditioned event datasets using the same temporal and economic protocol.

The initial model set is deliberately simple:

- empirical class prior
- multinomial logistic regression
- histogram gradient boosting

Deep models remain candidates for later stages. They do not receive a privileged path.

## Walk-forward contract

For each strategy identity, rows are sorted by event time.

Each fold uses:

```text
TRAIN
  ↓ embargo
VALIDATION
  ↓ embargo
TEST
```

Default sizes:

- minimum train: 240 events
- validation: 80
- test: 80
- step: 80
- embargo: 1 row
- maximum folds: 8

Model fitting uses TRAIN only.

Probability calibration uses VALIDATION only.

TEST is never used for fitting or calibration.

## Probability contract

Frozen axis:

```text
TP
SL
TIMEOUT
```

Candidate supervised models emit probabilities on that axis.

For learned models, per-class isotonic calibration is fit on validation probabilities and then applied to test probabilities.

Reported predictive metrics:

- multiclass LogLoss
- multiclass Brier
- accuracy

Accuracy is diagnostic only and does not control economic admission.

## Economic comparison

Every prediction path is replayed under:

```text
0 / 24 / 36 / 50 bps
```

Expected utility is:

```text
P(TP) × reward_fraction
- P(SL) × loss_fraction
- P(TIMEOUT) × timeout_loss_fraction
- cost
```

A test event is admitted only if:

- expected utility > 0
- normalized entropy <= threshold

Reported economic metrics include:

- coverage
- admitted event count
- mean realized return
- compounded return
- maximum drawdown
- profit factor

These are event-level research metrics, not a claim of live portfolio performance.

## Trial registry and multiplicity

Every attempted:

```text
strategy × model × fold × cost
```

is registered.

The system records:

- attempted-fold hash
- prediction hash
- trial result hash
- complete registry hash

This prevents reporting only favorable trials while hiding the search path.

## Promotion boundary

A tournament can never promote itself.

```text
promotable = FALSE
```

for every direct tournament result.

Real evidence may only set:

```text
promotion_review_eligible = TRUE
```

A separate holdout/promotion artifact is still required.

Engineering fixtures are never promotion-eligible.
